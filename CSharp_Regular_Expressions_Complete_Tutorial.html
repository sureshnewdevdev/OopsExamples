Lesson 01What is a regular expression?

A regular expression, usually called Regex, is a pattern used to find, validate, extract, replace or split text. Instead of writing many character-by-character checks, you describe the text structure that your application expects.

Imagine an employee registration application. Employee IDs follow the format EMP-1001, usernames allow only certain characters, and imported customer names contain extra spaces. Regex helps express these rules.

Workplace requirementRegex operation
Check an employee IDValidate
Read order references from a messageExtract
Clean repeated whitespaceReplace
Separate a mixed-delimiter fieldSplit
Regex checks text structure. An ID matching the correct format does not prove that the employee exists. Check existence separately.

Lesson 02How matching works

ComponentMeaningExample
InputText to examineEMP-1001
PatternRule to apply\AEMP-[0-9]{4}\z
OperationAction to performIsMatch()
1Read the input
2Apply the pattern
3Inspect match result
4Accept or report invalid input

The engine evaluates the pattern against the input. A search may find text anywhere in the input; a validation pattern should normally require the complete input to match.

Lesson 04First program: employee ID validation

Requirement: the input must contain EMP- followed by exactly four ASCII digits, with no extra text.

C# / Program.cs
using System;
using System.Text.RegularExpressions;

string employeeId = "EMP-1001";
string pattern = @"\AEMP-[0-9]{4}\z";
Regex employeeIdRegex = new Regex(
    pattern, RegexOptions.None, TimeSpan.FromSeconds(1));

bool isValid = employeeIdRegex.IsMatch(employeeId);
Console.WriteLine($"Employee ID: {employeeId}");
Console.WriteLine($"Valid: {isValid}");
Expected output
Employee ID: EMP-1001
Valid: True
Pattern partMeaning
\AAbsolute beginning of input
EMP-Literal characters
[0-9]One ASCII digit
{4}Exactly four repetitions
\zAbsolute end of input
InputValid?Reason
EMP-1001YesCorrect format
EMP-0007YesFour digits
EMP-101NoToo short
EMP-10001NoToo long
emp-1001NoCase differs
ABC EMP-1001NoExtra prefix
EMP-10A1NoLetter in numeric part
The one-second timeout is an example limit, not a universal setting. Choose an appropriate limit for your application and handle timeouts when processing external input.

Lesson 05C# string syntax: why patterns use @

The @ belongs to C# string syntax. It makes a verbatim string, allowing backslashes to be written directly. It is not a Regex operator.

C# / Program.cs
string normalPattern = "\\d+";
string verbatimPattern = @"\d+";

Both string forms above represent the same Regex pattern: one or more decimal digits.

C# expressionMeaning
@"\bcat\b"Regex word boundaries around cat
"\bcat\b"C# backspace characters around cat
"\\bcat\\b"Regex word boundaries using a normal C# string
There are two syntax layers: C# first creates a string, and the Regex engine then interprets the characters inside that string.

Lesson 06Forming patterns: literals and character classes

Ordinary letters and digits usually match themselves. The pattern Invoice finds that exact text anywhere in an input unless you add anchors.

PatternMeaning
[ABC]One character: A, B or C
[A-Z]One uppercase English letter
[a-z]One lowercase English letter
[0-9]One ASCII digit
[A-Za-z]One uppercase or lowercase English letter
[A-Za-z0-9]One English letter or ASCII digit
[^0-9]One character that is not an ASCII digit

For example, [A-Z][0-9] matches pairs such as A1, B7 and Z9. A character class describes one position unless a quantifier repeats it.

Lesson 07Shortcuts, quantifiers and anchors

ShortcutMeaning in normal .NET matching
\dA Unicode decimal digit
\DA character that is not a decimal digit
\wA word character, including Unicode letters, digits and underscore
\WA non-word character
\sA whitespace character
\SA non-whitespace character
.Any character except newline ( ), by default
\bA word boundary
Use [0-9] when identifiers must accept only ASCII digits. \d also accepts other Unicode decimal digits. \w does not mean English letters only.
QuantifierMeaningExample
*Zero or more[0-9]*
+One or more[0-9]+
?Zero or onecolou?r
{n}Exactly n[0-9]{4}
{n,}At least n[0-9]{2,}
{n,m}Between n and m[0-9]{2,5}

colou?r matches both color and colour: only the preceding u is optional.

AnchorMeaning
^Beginning of input, or a line with Multiline
$End of input or before a final newline; also line endings with Multiline
\AAbsolute beginning of input
\zAbsolute end of input

[0-9]{4} finds four digits inside Order 1234 created. In contrast, \A[0-9]{4}\z requires the entire input to contain exactly four digits.

Lesson 08Grouping, alternatives and escaping

SyntaxPurposeExample
|Alternation: choose one alternativePending|Approved|Rejected
(...)Group and capture(EMP|CON)
(?:...)Group without capturing(?:EMP|CON)
(?<name>...)Capture under a name(?<code>[A-Z]{3})
\.Match a literal dotreport\.csv

To validate a complete status, group the alternatives: \A(?:Pending|Approved|Rejected)\z.

Characters such as . ^ $ * + ? ( ) [ ] { } \ | have special meanings. Escape them when you need their literal form.

\Areport\.csv\z matches report.csv. An unescaped dot would permit a different character in that position.

Lesson 09Build a username pattern step by step

Requirement: start with an English letter, allow only English letters, digits and underscores, and require 5–12 characters in total.

StepRulePattern part
1Start of input\A
2First character is a letter[A-Za-z]
3Remaining permitted characters[A-Za-z0-9_]
44–11 more characters{4,11}
5End of input\z
The first character already counts toward the total. One initial character plus 4–11 remaining characters gives a length of 5–12.
C# / Program.cs
using System;
using System.Text.RegularExpressions;

Regex usernameRegex = new Regex(
    @"\A[A-Za-z][A-Za-z0-9_]{4,11}\z",
    RegexOptions.None, TimeSpan.FromSeconds(1));

string[] usernames =
{
    "Ravi_123", "1Ravi", "Ram", "Priya@123", "Training_User_2026"
};
foreach (string username in usernames)
    Console.WriteLine($"{username}: {usernameRegex.IsMatch(username)}");
Expected output
Ravi_123: True
1Ravi: False
Ram: False
Priya@123: False
Training_User_2026: False

Lesson 11IsMatch(): validate product codes

Product codes require three uppercase English letters, a hyphen and four ASCII digits.

C# / Program.cs
using System;
using System.Text.RegularExpressions;

Regex productCodeRegex = new Regex(
    @"\A[A-Z]{3}-[0-9]{4}\z",
    RegexOptions.None, TimeSpan.FromSeconds(1));

string[] codes = { "PRD-1025", "AB-1025", "PRD1025", "prd-1025" };
foreach (string code in codes)
{
    string result = productCodeRegex.IsMatch(code) ? "Accepted" : "Rejected";
    Console.WriteLine($"{code}: {result}");
}
Expected output
PRD-1025: Accepted
AB-1025: Rejected
PRD1025: Rejected
prd-1025: Rejected

IsMatch() gives a Boolean result. It does not return the matching text.

Lesson 12Match(): extract the first reference

A support message contains two order references. Retrieve only the first.

C# / Program.cs
using System;
using System.Text.RegularExpressions;

string message = "Please check order ORD-2045 before ORD-2099.";
Regex orderRegex = new Regex(
    @"\bORD-[0-9]{4}\b", RegexOptions.None, TimeSpan.FromSeconds(1));
Match match = orderRegex.Match(message);
if (match.Success)
{
    Console.WriteLine($"Order: {match.Value}");
    Console.WriteLine($"Position: {match.Index}");
    Console.WriteLine($"Length: {match.Length}");
}
else
    Console.WriteLine("No order number found.");
Expected output
Order: ORD-2045
Position: 19
Length: 8
PropertyPurpose
SuccessWhether matching succeeded
ValueMatched text
IndexZero-based starting position
LengthMatched character count
GroupsCaptured portions
If there is no match, Match() returns an unsuccessful Match object, not null. Check Success.

Lesson 13Matches(): extract every invoice reference

C# / Program.cs
using System;
using System.Text.RegularExpressions;

string message = "Paid INV-1001 and INV-1002; pending INV-1003.";
Regex invoiceRegex = new Regex(
    @"\bINV-[0-9]{4}\b", RegexOptions.None, TimeSpan.FromSeconds(1));
try
{
    MatchCollection matches = invoiceRegex.Matches(message);
    Console.WriteLine($"Invoice count: {matches.Count}");
    foreach (Match match in matches)
        Console.WriteLine(match.Value);
}
catch (RegexMatchTimeoutException)
{
    Console.WriteLine("Invoice search exceeded the time limit.");
}
Expected output
Invoice count: 3
INV-1001
INV-1002
INV-1003

Matches are evaluated lazily. When you handle timeouts, include collection access and enumeration inside the try block: a timeout can occur while retrieving the results.

Lesson 14Named groups: extract fields

An inventory record contains both a product code and quantity. Capture each field by name.

C# / Program.cs
using System;
using System.Text.RegularExpressions;

string record = "ITEM: PRD-1025; QTY: 12";
Regex recordRegex = new Regex(
    @"\AITEM:\s*(?<code>[A-Z]{3}-[0-9]{4});\s*QTY:\s*(?<quantity>[0-9]+)\z",
    RegexOptions.None, TimeSpan.FromSeconds(1));
Match match = recordRegex.Match(record);
if (match.Success)
{
    Console.WriteLine($"Product code: {match.Groups["code"].Value}");
    Console.WriteLine($"Quantity text: {match.Groups["quantity"].Value}");
}
else
    Console.WriteLine("Invalid record format.");
Expected output
Product code: PRD-1025
Quantity text: 12
Pattern partMeaning
ITEM: and QTY:Literal labels
\s*Zero or more whitespace characters
(?<code>...)Named product code capture
;Literal separator
(?<quantity>[0-9]+)Named capture of one or more digits
Captured values are strings. Use int.TryParse() and numeric checks before treating a quantity as an integer. A long digit sequence can match the pattern but exceed the range of int.

Lesson 15Replace(): clean and rearrange text

An imported customer name contains repeated spaces and a tab. Replace each whitespace sequence with one space, then trim the edges.

C# / Program.cs
using System;
using System.Text.RegularExpressions;

string original = "  Ravi    Kumar\tSharma  ";
Regex whitespaceRegex = new Regex(
    @"\s+", RegexOptions.None, TimeSpan.FromSeconds(1));
string cleaned = whitespaceRegex.Replace(original, " ").Trim();
Console.WriteLine($"Cleaned: [{cleaned}]");
Expected output
Cleaned: [Ravi Kumar Sharma]

\s+ matches one or more whitespace characters. Because this includes line breaks, the same replacement can flatten multiline text.

Rearrange a name using groups

C# / Program.cs
using System;
using System.Text.RegularExpressions;

Regex nameRegex = new Regex(
    @"\A(?<last>[A-Za-z]+),\s*(?<first>[A-Za-z]+)\z",
    RegexOptions.None, TimeSpan.FromSeconds(1));
string result = nameRegex.Replace("Kumar, Ravi", "${first} ${last}");
Console.WriteLine(result);
Expected output
Ravi Kumar

Replacement references ${first} and ${last} reuse captured values. This simplified pattern accepts single English-letter name parts only; it is not a universal personal-name validator.

Lesson 16Split(): handle mixed separators

C# / Program.cs
using System;
using System.Text.RegularExpressions;

string input = "HR,Finance;IT|Training";
Regex separatorRegex = new Regex(
    @"[,;|]", RegexOptions.None, TimeSpan.FromSeconds(1));
string[] departments = separatorRegex.Split(input);
foreach (string department in departments)
    Console.WriteLine(department.Trim());
Expected output
HR
Finance
IT
Training

Inside [,;|], the vertical bar is a literal separator, not alternation. Adjacent separators can produce empty strings; decide whether to reject or ignore them.

For fixed literal separators, string.Split() may already meet the requirement. Regex is useful when separators need a pattern. Capturing groups in a Split pattern can also cause captured separators to appear in the result; use non-capturing groups when appropriate.

Lesson 17RegexOptions: change matching behavior

OptionPurpose
NoneDefault matching
IgnoreCaseCase-insensitive matching
MultilineMake ^ and $ operate at line boundaries
SinglelineAllow . to match newline characters
IgnorePatternWhitespaceAllow formatting whitespace and comments in patterns
CultureInvariantCulture-independent behavior for relevant operations
C# / Program.cs
using System;
using System.Text.RegularExpressions;

string log = "WARN: Disk usage high. warn: Retry scheduled.";
Regex warningRegex = new Regex(
    @"\bwarn\b",
    RegexOptions.IgnoreCase | RegexOptions.CultureInvariant,
    TimeSpan.FromSeconds(1));
foreach (Match match in warningRegex.Matches(log))
    Console.WriteLine(match.Value);
Expected output
WARN
warn
Multiline and Singleline are independent. Multiline changes ^ and $. Singleline changes the dot. Enabling Multiline does not make the dot match across line breaks.

Lesson 18Regex.Escape(): use literal search text

A user searches for C++ (Basic). The plus signs and parentheses have Regex meanings, so escape the text when using it as a literal part of a pattern.

C# / Program.cs
using System;
using System.Text.RegularExpressions;

string searchText = "C++ (Basic)";
string courseList = "Courses: C# Advanced, C++ (Basic), SQL";
Regex searchRegex = new Regex(
    Regex.Escape(searchText), RegexOptions.None, TimeSpan.FromSeconds(1));
Console.WriteLine(searchRegex.IsMatch(courseList));
Expected output
True

Use Contains() for a simple literal substring search. Escape() is useful when literal user text is incorporated into a larger Regex pattern. It escapes pattern text, not replacement-string syntax.

Lesson 19Greedy and lazy matching

A line contains two bracketed tags: [HR] [IT]. A greedy quantifier consumes as much as it can while allowing a match; a lazy quantifier starts with as little as it can.

C# / Program.cs
using System;
using System.Text.RegularExpressions;

string input = "[HR] [IT]";
Regex greedyRegex = new Regex(
    @"\[.*\]", RegexOptions.None, TimeSpan.FromSeconds(1));
Regex lazyRegex = new Regex(
    @"\[.*?\]", RegexOptions.None, TimeSpan.FromSeconds(1));
Console.WriteLine($"Greedy: {greedyRegex.Match(input).Value}");
foreach (Match match in lazyRegex.Matches(input))
    Console.WriteLine($"Lazy: {match.Value}");
Expected output
Greedy: [HR] [IT]
Lazy: [HR]
Lazy: [IT]
PatternBehavior
\[.*\]One match spanning both bracketed tags
\[.*?\]Separate shortest matches in this example
\[[^\]\r\n]*\]Explicitly exclude closing brackets and line breaks inside a tag

A delimiter-specific pattern is often clearer than a broad dot. These examples are for flat tags and do not parse nested bracket structures.

Lesson 20Complete lab: support ticket processor

A support team receives ticket lines such as INC-1001: Login failed. Validate the reference, extract the description, clean extra spaces, reject invalid records and continue processing.

  • Reference starts with INC- and exactly four digits.
  • A colon separates the reference and description.
  • The description must contain a non-whitespace character.
  • Print each decision, then accepted and rejected counts.
1Read a ticket line
2Validate and capture fields
3Check and clean description
4Accept or reject; continue
C# / Program.cs
using System;
using System.Text.RegularExpressions;

string[] records =
{
    "INC-1001: Login failed",
    "INC-1002: Payment timeout",
    "INC-99: Invalid ticket number",
    "INC-1003:     ",
    "INC-1004: Printer offline"
};
Regex ticketRegex = new Regex(
    @"\A(?<ticket>INC-[0-9]{4}):[ \t]*(?<description>[^\r\n]+)\z",
    RegexOptions.None, TimeSpan.FromSeconds(1));
Regex whitespaceRegex = new Regex(
    @"[ \t]+", RegexOptions.None, TimeSpan.FromSeconds(1));
int accepted = 0;
int rejected = 0;

foreach (string record in records)
{
    try
    {
        Match match = ticketRegex.Match(record);
        if (!match.Success)
        {
            rejected++;
            Console.WriteLine($"Rejected: {record}");
            continue;
        }
        string ticket = match.Groups["ticket"].Value;
        string description = match.Groups["description"].Value.Trim();
        if (string.IsNullOrWhiteSpace(description))
        {
            rejected++;
            Console.WriteLine($"Rejected: {ticket} has no description");
            continue;
        }
        description = whitespaceRegex.Replace(description, " ");
        accepted++;
        Console.WriteLine($"Accepted: {ticket} | {description}");
    }
    catch (RegexMatchTimeoutException)
    {
        rejected++;
        Console.WriteLine("Rejected: matching exceeded the time limit");
    }
}
Console.WriteLine();
Console.WriteLine($"Accepted records: {accepted}");
Console.WriteLine($"Rejected records: {rejected}");
Expected output
Accepted: INC-1001 | Login failed
Accepted: INC-1002 | Payment timeout
Rejected: INC-99: Invalid ticket number
Rejected: INC-1003 has no description
Accepted: INC-1004 | Printer offline

Accepted records: 3
Rejected records: 2

Regex verifies the record structure and captures fields. Ordinary C# checks the trimmed description. Keeping a simple business check outside the pattern makes the rule easier to read.

Try these changes

  • Add a record with an empty description immediately after the colon.
  • Add a valid record containing repeated tabs or spaces in its description.
  • Add a lowercase inc- reference and observe case sensitivity.
  • Add a reference containing five digits and confirm rejection.

Lesson 21Common mistakes and reliable evaluation

MistakeEffectBetter approach
Unanchored validationA valid substring can pass inside invalid textUse \A and \z for complete-input validation
An unescaped dotMatches other charactersUse \. for a literal dot
Assuming \w means English lettersUnexpected characters are permittedUse explicit classes for restricted identifiers
Using * when text is requiredEmpty text may passUse +
Wrong C# escapingPattern changes or compilation failsCheck both string and Regex syntax
Ignoring Match.SuccessA failed match is misinterpretedCheck Success before reading fields
Matching date shape onlyImpossible dates may passUse DateTime.TryParseExact()
Matching digits onlyRange or overflow problems remainUse TryParse() and numeric checks
Recreating a Regex in a loopUnnecessary setup workCreate once and reuse

Test valid input, invalid input, empty input, extra prefixes and suffixes, boundary lengths and near-matches. If input may be null, handle it before calling Regex methods.

Avoid ambiguous nested repetitions such as (a+)+. Backtracking patterns can take excessive time on some near-matching inputs. Use trusted patterns, reasonable input limits, appropriate timeouts and timeout handling. An invalid pattern can throw ArgumentException when the Regex is constructed; fix application-owned patterns rather than treating that as ordinary bad user input.

A timeout is a matching time budget, not a universal security boundary. The one-second limit used in examples should be adjusted to the workload.

Lesson 23Practice questions

  • Validate department codes containing exactly three uppercase letters followed by two digits, such as HRD12.
  • Extract every order reference in the format ORD-12345 from a customer message.
  • Clean repeated spaces and tabs from an imported address.
  • Split a skill list separated by commas, semicolons or vertical bars and ignore empty entries.
  • Extract code and quantity from Product=PRD-2045;Quantity=18.
  • Validate usernames containing 6–15 characters, beginning with a letter and containing only English letters, digits and underscores.
  • Find the whole word error in a log message without case sensitivity.
  • Replace dates written as 2026-11-02 with 02/11/2026 using groups, and separately check whether each date is valid.
Method recap: IsMatch checks; Match finds the first; Matches finds all; Replace changes; Split separates; Escape treats pattern characters literally.
